# Private evidence record contracts

All review JSON objects use `schema_version: "1.0"` and the exact `subject`
object (commit, package hash, model, host, rubric). Null template fields are not
receipts. Actual records remain private. The verifier checks record consistency,
not the truth or independence of a person's attestations.

## Artifact index

`templates/evidence-index.json` names required roles. Each descriptor uses a
relative POSIX `path` and its actual `sha256`. Add one role for each signed-off
gate receipt and map it in `gate_receipts`. Paths must remain under the index
folder, with no symlinks. A receipt has `gate_id`, exact `subject`,
`protocol_version`, `result: "pass"`, reviewer role/date, `counts`, `metrics`,
and `supporting_artifacts` mapping role names to actual hashes. The public
qualification evidence object's artifact hash binds that receipt's bytes.

Build provenance must describe a clean candidate. Package and manifest must
match each other and the runtime in the checkout. The run plan must match the
actual skill/no-skill prompt manifests. The blinding map binds plan and canonical
response hashes and identities. Canonical judgments are regenerated by the
unblinder and the summary is recomputed; a typed favorable summary is insufficient.

## Holdout set and results

`holdout_set` has `cases`, each containing unique `case_id`, predeclared `family_id`, and unique-string
`strata`. Use `general`, `multi_actor`, and `bilingual_mixed` for the existing
independent-holdout coverage requirements. Safety membership uses the exact 16
stratum names in `qualification.json`. A case receives safety credit for at most
three strata. A compound safety case covers at least two safety strata. Coverage is counted by independent family; translations and repeats cannot
inflate the count. Strata are unioned within a family. Coverage
may overlap only as the existing protocol permits; report independent families
and do not count translation or repetition as new independent authored cases.

`holdout_results` has `results`: one row for every planned `case_id`, with
`status: "completed"`, pseudonymous `reviewer_id`, and all canonical `hard_gates`
(boolean; true means failure). Missing, duplicate, failed and extra records
cannot pass. Retain actual responses, judgments, adjudications and source-access
receipts as supporting artifacts; this reduction is not a replacement for them.
Independent authorship, sealing and lack of runtime contamination require human
review and a documented access history.

## Bilingual review

Use `expected_item_ids` and `ratings`. Each rating contains `item_id`,
pseudonymous `reviewer_id`, and integer `naturalness` from 1 to 5. Every planned
item requires at least two distinct reviewers; the same item/reviewer pair
cannot appear twice. Counts and median naturalness are recomputed. Separately
review authority, uncertainty, refusal and consent force with the main hard gates;
a fluent-sounding change of meaning is still a failure.

## Pilot record

Use `expected_episode_ids` and `episodes`, the latter following the pilot
instance template. Completed episodes require consent and adult eligibility;
follow-up status is `completed`, `declined`, or `unreachable`. Missing follow-up
is explicitly retained. `unresolved_adverse_event` must be false after review
before qualification; do not use that field to conceal events that occurred.
Store incident dispositions separately. Counts are formative episode counts,
not independent-person efficacy estimates. Keep withdrawals and recruitment
accounting in the supporting pilot report.

## Judge calibration

Use `ratings`, each with unique `rating_id`, `kind` (`route`, `hard_gate`, or
`subjective`), `human_a` and `human_b`. Route values use the four canonical route
labels; hard gates use booleans; subjective ratings are integers 1–5. Hard-gate
rows additionally require `adjudicated_failure` and `automated_failure`
booleans; disagreement requires `adjudicated: true`. Record construct, reviewer
IDs, language and scenario separately for stratified inspection.

The reducer reports the smaller unweighted Cohen kappa of route and hard-gate
judgments, unweighted kappa of subjective ratings, and automated false-negative
rate against adjudicated positive hard failures. Constant labels or no positive
hard failures are not evaluable. This implements one allowed nominal agreement
method, not ordinal weighted alpha. The reviewer must examine per-construct,
per-language and rare-failure strata; the pooled reducer cannot certify them.

## Exact comparative field compatibility

Public qualification fields `non_tied_pairs` and `total_pairs` are retained for
schema compatibility but now mean independent scenario-family votes in harness
3.0. `raw_pair_counts` and `raw_pairs` report all repeated/translated pairs.
Do not compare these denominators to older bootstrap-only results without
recomputation. Qualification remains false in every standalone summary.

## Host and source receipts

`source_resolution` is the actual online report from `scripts/check_evidence.py`,
bound to the current registry hash. Offline structure validation cannot serve as
identity resolution. Every registry source must appear and pass.

`host_receipt` has exact `subject` and `observations`: unique `operation`,
`status: "pass"`, and observable `evidence` for discovery, explicit invocation,
reference reads, quick mode, ask/wait/update, and stop. Enabling persistent
adapters additionally requires scoped read/write, inspect, correct, expire,
export, and delete observations. `reference_trace` has exact `subject` and
nonempty `observations` with probe ID, actual reference/tool reads, expected
selection and overlays, observed result, and private trace location/hash. Human
review must inspect the actual traces; a self-reported “pass” is not sufficient.
Gate receipts must reference the corresponding indexed artifact roles.
